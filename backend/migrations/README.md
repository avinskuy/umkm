# Migrasi Database

Direktori ini berisi migration SQLx berversi. Migration Identity Core yang tersedia:

- `20261121170000_create_identity_accounts.sql` — membuat `users` dan `user_identities`, constraint lifecycle/role/kontak, unique partial index reservasi kontak, trigger immutability, transisi lifecycle 30 menit/30 hari, pemeriksaan metode autentikasi, serta fungsi `create_client_user` yang hanya menerima role Business Owner atau Investor.
- `20261122100000_create_identity_verification.sql` — membuat `verification_sessions`, `verification_challenges`, `otp_verification_attempt_events`, dan `otp_delivery_events`, termasuk state constraints, batas umur challenge 10 menit, satu challenge pending per sesi, binding recovery pra-pemilihan akun, serta indeks event lintas sesi.
- `20261122110000_create_identity_sessions.sql` — membuat `sessions` dengan hash token SHA-256 unik, batas absolut 30 hari, batas idle 7 hari, rotasi token, pencabutan individual, metadata perangkat minimum, serta pencabutan otomatis saat status lifecycle akun tidak lagi aktif.
- `20261122120000_create_account_recovery.sql` — membuat `recovery_contacts` dengan relasi lintas akun yang diizinkan dan deduplikasi per akun, `account_recovery_cases` dengan pemilihan target setelah verifikasi, serta `password_reset_tokens` yang hanya menyimpan hash dan terikat ke kasus/akun.

Migration 0001 menyediakan identitas akun dan provider identity. Migration 0002 menyediakan skema verifikasi; runtime OTP, provider, abstraksi key provider, dan enforcement rate limit masih belum diimplementasikan. Batas kebijakan lintas sesi ditetapkan maksimal lima kegagalan per kontak dalam jendela bergulir 60 menit, tetapi enforcement baru berlaku setelah runtime transaksi PostgreSQL diimplementasikan. Migration 0003 menyediakan penyimpanan sesi autentikasi, tetapi belum menyediakan endpoint login/logout, validasi cookie, middleware autentikasi, atau integrasi runtime. Migration 0004 menyediakan skema kontak pemulihan, kasus pemulihan, dan token reset; runtime tetap wajib mencocokkan kontak terverifikasi dengan akun target, menjalankan pemeriksaan risiko, menerbitkan/mengonsumsi token secara atomik, memperbarui password, mencabut sesi, dan menulis audit event. Batas idle 7 hari dan absolut 30 hari tetap harus diperiksa pada setiap permintaan oleh backend; opsi ingat perangkat tidak mengubah batas tersebut. Tidak ada grant runtime atau provisioning Admin yang dibuka secara otomatis oleh migration ini; hak akses tiap principal harus disiapkan terpisah sesuai kebijakan least privilege.

Migrasi dijalankan secara eksplisit melalui `database::migrations::run(&pool)`. HTTP server belum menjalankan migrasi atau menginisialisasi database pada startup. Migration 0001–0004 belum dijalankan terhadap database produksi dan tidak boleh dianggap sebagai aktivasi fitur registrasi/login atau pemulihan akun.

Pengujian PostgreSQL untuk migration dan invariant identitas berada di `backend/tests/postgres.rs`. Gunakan database sementara yang dapat dibuang, bukan database produksi.

Jangan pernah mengubah migration setelah diterapkan pada database bersama. Perubahan skema berikutnya harus menggunakan migration baru dengan versi SQLx berikutnya.
